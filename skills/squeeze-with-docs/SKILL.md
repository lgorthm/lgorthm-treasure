# squeeze-with-docs

把 squeeze 的逐轮对话变成可浏览的问题解答树：每页先给当前层足够有用的答案，再链接到下一层；由 AI 完成递归展开，让读者控制阅读方向与深度。

## 启用与适用边界

- 仅在用户明确调用本技能时使用；仅提到技能名称、讨论其规则，或问题很宽泛，都不算调用。
- 后续对同一文档的补充、修正、展开沿用本技能；新话题不自动继承。用户要求退出或改变形式时，遵从该要求。
- 本技能独立包含 squeeze 的共同方法，不需要先执行 squeeze；不要继承它的逐轮等待步骤。
- 对单个事实、明确操作、聚焦判断等没有合理拆解空间的问题，直接完整而简洁地回答。除非用户要求落盘，否则不为它创建文档树；明确要求文档时，一页即可。
- 本技能控制解释的组织与交付方式。用户同时授权的执行任务仍需完成，不能用生成说明文档代替实际工作。

## 1. 确定范围与落点

从用户的问题、已有上下文和可读取资料中提取核心问题、读者背景、目标与边界。有信息可查时先查，不让用户替 AI 查代码或资料。

用户已给出输出路径时使用该路径；否则沿用项目既有文档位置，没有约定时写入当前工作区的 `docs/squeeze/<topic>/`，以 `README.md` 为入口。选用简短、稳定的主题名；目录已存在而用途不同，则另建目录，不覆盖无关文档。使用用户的语言。

缺少背景但仍能解释时，在入口写明简短假设，直接继续。对于未知偏好，给出按条件区分的答案，不代用户做决定。只有缺少关键输入导致无法产生可信答案时，才询问最小必要问题；无需为目录、普通拆分或深度反复确认。

## 2. 建立问题树

先规划，再递归写作。维护一个内部节点清单，记录每个问题的父节点、路径、依赖及完成状态；简单任务可直接在工作计划中记录，无需额外交付清单文件。

- **根节点先给地图。** 提炼核心答案与一组同层级问题。每项都写一句有信息量的摘要，让读者能判断是否值得点开。
- **每次只拆一层。** 对当前节点寻找更具体的直接子问题，同层条目采用一致的拆解维度。随后由 AI 自行对各子节点重复这一过程，不等待用户选择；不能只把父问题换个说法后继续递归。
- **子问题必须增加价值。** 只有具有独立阅读价值、能解释机制、依据、步骤、取舍或边界的问题才单独成页。一两个句子能说明的内容留在当前页。
- **到叶子就回答。** 当问题足够具体时，给出能解决它的内容，包括必要的例子、步骤、理由或限制，不继续切碎。
- **共享概念只解释一次。** 将已有完整解释作为规范节点，其他分支简述其关联并链接过去。发现重复问题或循环依赖时复用节点，停止这条递归。

范围有限，递归也应有限。“全部展开”指完成本次范围内所有有意义的分支，不是穷举一个主题的所有知识。按问题复杂度选择不均匀的深度；不设必须凑满的层数、分支数或页数。用户指定的深度、篇幅、时间或 token 上限优先。

## 3. 自动回答所有分支

从根逐层展开，优先完成其他答案依赖的节点。需要并行时，可以将独立分支交给子代理；统一术语、路径和共享节点，最终由主代理检查一致性。

每个页面都应让读者在当前层获得实质答案，不能只有标题或一个空目录。父页概括，子页增加解释；不要在各层重复粘贴同一段答案。必要结论、前提和关键限制就在当前页说明，不把它们藏在深层链接后。

自行回答问题不等于自行编造事实。区分已核实的事实、推断与假设；对代码问题检查实际代码，对技术或易变事实遵循当前环境的文档查询与查证规则。把实际使用的来源链接放在相关答案附近；离线或来源不足时明确限制，不能伪造引用或确定性。项目未来决策用条件表达，不自动记录为已经达成的正式决策。

在资源充足时，持续完成已规划的全部分支，不以“想看哪部分”“回复编号继续”结束。若确实达到资源限制，先交付已有的完整答案，在入口准确列出尚未展开的范围与原因；删除空页与未生成目标的链接，不把部分完成描述为全部完成。

## 4. 组织 Markdown 导航

采用一个主题入口、一个问题一页的目录结构。分支节点与叶子节点均可用各自目录内的 `README.md`，便于后来追加子问题：

```text
docs/squeeze/<topic>/
├── README.md
├── 01-first-question/
│   ├── README.md
│   └── 01-specific-question/
│       └── README.md
└── 02-second-question/
    └── README.md
```

文件名使用短小的 ASCII kebab-case，可加同层序号；页面标题与链接文字保留用户的语言，并写清要回答的问题。既有文档更新时保留稳定路径，不因重排目录而无故重命名。

每页按需要包含以下内容，不机械凑齐栏目：

1. **导航。** 子页顶部提供「返回总览」「返回上一级」的真实相对链接；必要时附面包屑。根页无需返回链接。
2. **当前问题的答案。** 标题后先给直接回答；根页同时说明本次范围与必要假设，叶子页给足具体内容。
3. **下一层问题。** 分支页列出直接子问题，每项包含链接和一句实质摘要；叶子页无需制造“继续深入”。
4. **相关问题与依据。** 有用时添加跨分支链接、例子和来源，不强制为每页附无关栏目。

例如，位于 `01-first-question/README.md` 的导航可以写成：

```markdown
[返回总览](../README.md) · [返回上一级](../README.md)

# 当前问题？

先给这一层足够有用的回答。

## 深入阅读

- [具体子问题？](01-specific-question/README.md)：说明读完能理解什么。

## 相关问题

- [另一分支的问题？](../02-second-question/README.md)：说明两者的联系。
```

文档间使用相对文件链接，让整个目录移动后仍可阅读；不要依赖特定编辑器协议、绝对本机路径或自动生成的标题锚点。每个非根页面都应被入口或某个可达页面链接到。外部引用使用真实来源 URL，来源文件可使用合适的相对路径。

## 5. 检查并交付

完成写作后检查节点清单：计划分支是否都有答案，叶子是否足够具体，同层是否重复或混杂，事实与条件是否前后一致。

运行随本技能提供的检查器：

```sh
python3 <skill-dir>/scripts/validate_docs.py <document-root>
```

将占位符替换为本技能目录与本次主题目录。检查器检查 Markdown 文件链接是否有效、页面是否从根入口可达，忽略外部 URL；它不验证锚点或答案质量。修复发现的问题后再交付。若运行环境没有 Python，使用可用工具完成相同检查并说明验证方式。

再人工检查各子页的返回入口与父级链接、摘要是否有信息量、所有链接文字与目标是否对应；链接存在不等于回答正确。

最后在对话中给出可点击的入口文件链接、简短范围说明及实际存在的限制。无需把所有页面再粘贴到对话中，也不要求用户逐项选择后才生成剩余答案。后续用户指定某个节点时，更新该节点及受影响的摘要、链接，再做同样检查。
